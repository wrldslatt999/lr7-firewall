# Структура правил, конфлікти й порядок застосування

Значення `0` для `src_port`/`dst_port` означає будь-який порт. CIDR завжди нормалізується як IPv4-мережа; `action` = `allow` або `deny`; `proto` = `TCP` чи `UDP`; `direction` = `in` або `out`. Правило має незмінний ID, логічний стан `enabled` і цілочисельний пріоритет від 1 до 1000.

## Точний порядок

1. Менше значення `priority` означає вищий пріоритет.
2. Для двох правил з однаковим пріоритетом першим розглядається `deny`.
3. Якщо пріоритет і дія збігаються, першим розглядається менший ID.
4. Діє **перше** увімкнене правило з повним збігом IP-адрес, портів, напряму й протоколу.
5. Без збігу спрацьовує `default_action` (за прикладом викладача `allow`).

## Виявлення

- Ідентичні правила за всіма полями, крім ID, відхиляються як `duplicate_rule` (`409`).
- Мережеві діапазони вважаються такими, що перекриваються, якщо одночасно перекриваються `src_ip_cidr`, `dst_ip_cidr`, порти (включно із wildcard) та збігаються напрям і протокол.
- Різна дія для двох активних правил, що перекриваються, дає `conflict`, однакова — `overlap_same_action`.
- Виявлений перетин **не забороняє** додати правило: API показує його в `warnings` і `GET /conflicts`, а фінальне рішення визначається детермінованою пріоритетністю.
- Вимкнені правила не впливають на рішення й не беруть участі у виявленні поточних конфліктів.

Виявлення перетину не є формальним доведенням досяжності чи повного затінення правила: воно відображає потенційну ділянку конфлікту. Для великої політики потрібні додаткові методи аналізу.
