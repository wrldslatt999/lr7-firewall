# Модель загроз та обмеження

- **Межа захисту:** фільтруються лише потоки, які явно використовують налаштований TCP/UDP-проксі. Фізичний інтерфейс, ядро та інший трафік ОС не контролюються.
- **Адміністрування:** `127.0.0.1`, `X-Admin-Token` із CSPRNG, файл секрету з Unix-правами `0600`, обмежена довжина JSON. API не призначений для віддаленої мережі. Рекомендовано захистити локальний обліковий запис.
- **Конфігурація:** `config.json` змінюється атомарно; одночасні зміни правил синхронізовані RLock; зміна мережевих слухачів без перезапуску не допускається.
- **Журнали:** UTC-час, ID правила, причини відмов; не містять payload/паролів. Рекомендовано ротацію й обмеження доступу.
- **TCP:** політика перевіряється на кожне нове з'єднання до proxied listener, а не для кожного TCP-сегмента. Існуючий TCP-потік не переривається при додаванні нового deny-правила.
- **UDP:** перевіряється кожна датаграма окремо, пересилання на один конфігурований endpoint, отримання однієї відповіді з таймаутом.
- **Fail-open policy:** у прикладі викладача implicit `allow`; для політики заборони за замовчуванням змінити `default_action` на `deny` і додати явні allow-правила.
- **Немає:** IPv6/ICMP, kernel hooks, аналізу payload, DPI, NAT, stateful tracking, DoS-стійкості чи production-hardening.
